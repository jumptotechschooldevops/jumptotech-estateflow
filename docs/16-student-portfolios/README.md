# 16 · Student Portfolios

**Prerequisites:** [06-engineering-records](../06-engineering-records/README.md), [15-star-interview-portfolio](../15-star-interview-portfolio/README.md)
**Next step:** none — this is where everything else in this documentation set accumulates.

A portfolio is **your own** record, in **your own** GitHub repository (not a fork of this
one, and not a folder added to this one) — a living collection of evidence that you actually
did this work, built up over the course of working through
[00-start-here](../00-start-here/README.md) through
[13-student-assessments](../13-student-assessments/README.md). Instructors and future
interviewers can look at it directly.

## What a portfolio should contain

| Section | Pulled from |
|---|---|
| Architecture explanation (in your own words) | [01-architecture](../01-architecture/README.md), practiced via [13-student-assessments/03](../13-student-assessments/03-architecture-verification-checklist.md) |
| Deployment records | Your own [execution records](../06-engineering-records/README.md) from [02-deployment-guides](../02-deployment-guides/README.md) |
| Commands executed | Same execution records — real, pasted, not paraphrased |
| Screenshots and test results | From every [13-student-assessments](../13-student-assessments/README.md) submission |
| Incident tickets | From [14-incident-simulations](../14-incident-simulations/README.md) exercises you ran |
| Incident reports | Completed [incident report templates](../05-incident-management/03-incident-templates.md#incident-report-template) |
| Root cause analyses | The root-cause section of each incident report |
| Pull Requests | Links to real PRs you opened, per [07-change-management](../07-change-management/README.md) |
| Runbook contributions | Any runbook you wrote, fixed, or improved |
| STAR interview stories | Your own versions from [15-star-interview-portfolio/13](../15-star-interview-portfolio/13-editable-template.md) |
| Final assessment results | Your scored [capstone exam](../13-student-assessments/09-final-capstone-examination.md) outcome |

## Where this lives

In **your own** GitHub repository — create a new, separate repo (e.g.
`your-username/devops-portfolio`), copy the template, and keep it updated as you progress.
Never put real credentials, tokens, account IDs, or other sensitive details in a public
portfolio repo — use the same placeholder conventions this documentation uses throughout
(`<ADMIN_API_TOKEN>`, `<AWS_ACCOUNT_ID>`, etc.).
