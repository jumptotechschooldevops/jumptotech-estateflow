# 06 · Grading Rubric (100 Points)

**Prerequisites:** none — referenced by every assessment in this folder
**Next step:** [07 · Student submission template](07-student-submission-template.md)

This single rubric is used across assessments 01–05 and the capstone (09) — individual
assessments may note which categories are weighted more or less heavily for that specific
exercise, but the 100-point structure stays the same for consistency.

| Category | Points | What earns full marks |
|---|---|---|
| **Correct execution** | 25 | All required tasks completed, in a working state, verified by the stated verification commands |
| **Evidence quality** | 20 | Real, unedited command output and screenshots showing the student's own environment; no paraphrased or invented output |
| **Understanding demonstrated** | 20 | Written explanations are specific and correct, in the student's own words — not copied from documentation |
| **Troubleshooting process** | 15 | Diagnostic steps are systematic (read-only first, hypothesis-then-verify), not random trial-and-error; mistakes are documented honestly, not hidden |
| **Documentation quality** | 10 | Submission uses the correct template, is organized, and is readable by someone who wasn't there |
| **Safety and judgment** | 10 | No destructive command run without justification; correctly identifies when something would need escalation/approval in a real environment |

**Total: 100 points.**

## Score bands

| Score | Outcome |
|---|---|
| 90–100 | Excellent — ready for the next assessment/capstone without reservations |
| 70–89 | Pass — solid work, review instructor feedback before the next assessment |
| 50–69 | Fail, resubmission encouraged — specific gaps identified in instructor feedback |
| Below 50 | Fail, recommend repeating prerequisite labs before resubmission |

## Automatic-fail conditions (regardless of point total)

- Evidence that the work was not performed by the student themselves (e.g. identical
  terminal output/screenshots to another student's submission, or output that doesn't match
  claimed environment details)
- Fabricated command output (a claimed result that doesn't match what the command would
  actually produce)
- A destructive command run against a shared/production-labeled environment without approval

## Note on partial credit

Partial credit is expected and normal — a student who correctly diagnoses a problem but runs
out of time before fully resolving it should score well on "Troubleshooting process" even
with a lower "Correct execution" score. Grade what was actually demonstrated.
